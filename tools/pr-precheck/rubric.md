# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | The diff's changed files and hunks, read against the plan's stated files and scope (its in-scope and not-in-scope lines) and its deviation notes | Pass if every changed file falls inside the plan's stated files or scope, or is explained by a deviation note, and every change the plan names is in the diff or its absence is disclosed in the description or the deviation notes. Fail if the diff touches a file or area that neither the plan nor a deviation note names, or if a change the plan names is missing from the diff with no disclosure. | required |
| description-matches-diff | Each claim in the PR title and description (what changed, what was tested, what was left out, the issue it closes), read against the diff lines and the test evidence | Pass if the main claims of the description are backed by a line in the diff or by a stated result in the test evidence. A claim that something was not added counts as backed if nothing in the diff adds it. A routine-hygiene claim (code formatted, lint clean) that nothing in the package contradicts is not a failure, and a small imprecision in a count or a list is not a failure when the main claim is backed. Fail if a main claim is contradicted by the diff, or names a change, file, or result that the diff and the test evidence do not contain at all. | required |
| test-evidence-observable | The test evidence, read against the plan's test plan and the reproduction's steps | Pass if the evidence shows the command from the plan's test plan or the reproduction and the concrete result observed before and after the change (printed output, or a specific stated observation such as the exact error text, the rows listed, or "no error"), and the after result matches what the plan said to expect. Fail if the evidence is only a general sentence that tests pass or the fix works, shows no concrete before or after result, or re-runs something other than what the plan's test plan names. | required |
| repo-checks-run | The test evidence, read against the checks that the PR template and the repo-facts block list | Pass if every check the template or the contribution guide lists appears in the test evidence or the description with its result (printed output, or a plainly stated result such as a pass count or "clean"), or the description honestly states which check was not run or failed and why. Fail if a listed check is never reported at all, or a Testing box is ticked for a check with no result behind it. | required |
| diff-reviewable | The unified diff and the commit list | Pass if every hunk serves the stated change. Fail if the diff contains debug prints, commented-out code, dead code, formatting-only churn, or an unrelated edit, even inside a file the plan names. | required |
| standards-and-disclosure | The description and the diff, read against the repo-facts block's PR template asks, contribution asks, and AI-use policy, and against any explicit maintainer direction in the thread highlights | Pass if every ask the repo-facts block lists for the template or the contribution guide is met in the description or the diff (for example a changelog or whatsnew entry in the diff, a type-of-changes or checklist section filled in, the issue named by number, the repo checks reported), and, where the repo's stated policy requires disclosing AI assistance, the description contains that disclosure. Treat every package as AI-assisted work, so a stated disclosure requirement applies. Fail if an ask the repo-facts block lists is unmet (a required entry missing from the diff, a section empty or left as placeholder text, the issue not named by number, a stated check never reported), if a stated AI-disclosure requirement is not met, or if the diff or description contradicts explicit maintainer direction in the thread. If the repo states no AI policy, a description with no AI disclosure is not a failure. | required |

## Verdict rule

Accept (ready to submit) if every check passes. Reject (hold) if any check fails. A grade of unclear on any check counts as a fail. A shortfall that the description or the plan's deviation notes honestly disclose does not make a check fail on its own: the checks above say where a disclosure satisfies them.
